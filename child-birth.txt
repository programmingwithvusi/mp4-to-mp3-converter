2. Push the new branch and set it as the one you track

git push -u origin main

This pushes main as a new branch on GitHub — master still exists on the remote at this point too, untouched.

3. Change the default branch on GitHub

Go to your repo → Settings → Branches (or Settings → General on older UI) → under "Default branch," click the swap icon next to master → select main → confirm.

This matters because it controls: what branch PRs default to, what shows when someone opens the repo, and which branch is implied for various GitHub features. Do this before deleting master — GitHub won't let you delete a branch that's still marked default.

4. Delete the old master branch on GitHub
git push origin --delete master

Or via the GitHub UI: branches list → trash icon next to master.

5. Update local remote tracking cleanup
git remote set-head origin -a

This refreshes what origin/HEAD points to locally, so git status and related commands stop referencing the now-deleted master.

6. Revert deploy.yml back to main

Since we just changed it to master in the last step — flip it back:

yaml
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

And in the Netlify deploy step:

yaml
production-branch: main
production-deploy: ${{ github.ref == 'refs/heads/main' && github.event_name == 'push' }}

Commit and push:
git add .github/workflows/deploy.yml
git commit -m "Switch branch trigger back to main"
git push origin main

7. Update Netlify's dashboard setting too

Site settings → Build & deploy → Continuous deployment → Production branch → change to main.

8. Anything else pointing at master

Quick sweep for other references:

Select-String -Path * -Pattern "master" -Recurse -Exclude node_modules -ErrorAction SilentlyContinue

Common places this bites people: branch protection rules (recreate them under main if you had any set on master), README badges linking to .../master/... paths, and any other CI config referencing the branch name.

9. If you have local clones elsewhere or collaborators

Anyone else with a local clone needs to run:

git fetch origin
git checkout main
git branch -d master  # deletes their now-stale local master
git remote set-head origin -a

Once steps 1–4 are done, your test-deploy-pipeline branch situation from earlier resolves too — merging that PR into main (the new default) will correctly match the trigger you're reverting to in step 6.
